# Where the templates in apps-render.jsonl come from.
#
# Everything else in the corpus is a weather station or a provisioning
# server, and a corpus of one habit finds only the rules that habit
# uses. These are the repositories GitHub returns for two questions:
# who imports Cheetah or declares it a dependency, and where the syntax
# itself stands. The second one is the better half, because it finds
# the projects that vendored it: #slurp, #errorCatcher, #end block,
# #compiler-settings, cheetahVarStartToken.
#
# What came back is a different world. JPL's flight software generates
# C++ headers with it. An Enigma2 satellite receiver builds its web
# interface with it. A voting system, an imageboard, a rack database, a
# LaTeX resume. Templates written by people who never saw a skin.
#
# Which of the files is a Cheetah template at all is not decided by
# this list. A ".tmpl" is claimed by half a dozen engines and a ".inc"
# is usually a C header; the harvest asks for Cheetah syntax, then asks
# ct3 to compile it, and then asks Python to read what ct3 wrote. Two
# thousand six hundred files fail one of the three.
#
# To fetch and harvest them again:
#
#   python -m ct4.corpus fetch-skins --out /tmp/apps \
#       --sources corpus/app-sources.txt
#   python -m ct4.corpus harvest-app-templates /tmp/apps
